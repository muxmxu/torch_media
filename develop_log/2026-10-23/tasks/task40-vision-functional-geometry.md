## Objective
`torchmedia::vision::functional` reproduces the torchvision 0.20.1 `transforms.v2.functional` tensor kernels for
resize / crop / center_crop / pad / resized_crop / five_crop / ten_crop / to_dtype and the 7 initial ops, point-wise,
on uint8 and floating images with any leading dims.

## Scope
In:
- `_vision/_functional.hpp`: `interpolation_mode`, `padding_mode`, the ops above (progress07 D2), uint8 resize
  dispatch (D3), fixes of invert / adjust_brightness / rgb_to_grayscale / normalize / center_crop (D4).
- `unit_test/vision/functional/{main.cpp, gen_golden.py, golden.hpp}`.
Out:
- Random / color-jitter / affine ops; PIL semantics; bounding boxes and masks.

## Inputs (read first, priority order)
1. `.venv/.../torchvision/transforms/v2/functional/{_geometry.py, _color.py, _misc.py}` — the reference kernels.
2. `.venv/.../torch/nn/functional.py` `interpolate` — which `upsample_*` overload each mode dispatches to.
3. `develop_log/2026-10-23/progress02` D2-D11 — error and dtype / device conventions.

## Deliverables
- Signatures mirroring torchvision positionally; `std::invalid_argument` for every torchvision validation error.
- `golden.hpp` generated by `gen_golden.py`: the 3 seeded inputs + 91 expected outputs, each with its dtype.

## Acceptance criteria
- [x] Every golden matches in dtype, shape and value with zero tolerance on arm64: resize in 4 modes x antialias on /
  off x uint8 / float32 (up 5 x 7 -> 8 x 11, down 11 x 13 -> 4 x 5) and float64, batch / 5-D, shorter edge,
  max_size cap, size None, MPS bilinear; crop in / out of bounds and 2-D; center_crop half-even anchors and three
  padding shapes; resized_crop; five / ten crop (h and v flip); pad in all modes, scalar / vector / negative padding,
  float64 vector fill through float32; to_dtype in 11 conversions; grayscale, brightness, invert (uint8, int8 / 16 /
  32 / 64, float), normalize (float32, float64, scalar mean / std, inplace).
- [x] Every validation branch throws `std::invalid_argument`; a zero output size stays `c10::Error`.
- [x] `_functional.hpp` 100% line coverage (`llvm-cov report`).
- [x] Dev-time sweep (progress07 G1): 2347 / 2348 cases bit-exact, the remaining one a documented deviation (D7).

## Constraints
- Same libtorch ops as torchvision (bit-exact on the same machine); header-only, `inline`, `std::format`.

## Notes / Assumptions
- Breaking change: `center_crop(img, h, w)` -> `center_crop(img, {h, w})`.
- uint8 bilinear goldens come from the float32 path (arm64 "NO AVX"); AVX2 machines take the native kernel.
